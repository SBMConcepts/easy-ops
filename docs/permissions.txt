===============================================================================
 EasyOps — RBAC Permission Catalog
===============================================================================
 Source of truth : public.role_permissions  (DB)
 Vocabulary      : public.app_permission enum
 Propagation     : the frontend reads role_permissions directly (RLS policy
                   "role_permissions_read_own_role" exposes the caller's role
                   grants). No external IdP mirror — Supabase Auth is the only
                   identity provider.
 Enforcement     : frontend -> usePermissions().hasPermission()
                   DB        -> Postgres RLS via current_tenant_id() /
                                has_tenant_role() + table policies
                   privileged ops -> Supabase Edge Functions (service role)
                                     verify the caller before mutating

 Roles (tenant_role, high -> low): owner > admin > manager > supervisor > employee
   'owner' is a DB-only superset (every permission). The application uses
   'admin' as its top operating tier.

 Legend: [x] granted   [ ] not granted   (status: IMPL = wired to a route today,
   ENUM = in the enum/seed but no dedicated route yet)
===============================================================================

C. DATA ACCESS -> ENFORCEMENT MAP  (Supabase; RLS + Edge Functions)
-------------------------------------------------------------------------------
  Most reads/writes go straight to Supabase from the client and are enforced by
  Postgres RLS (tenant-scoped via current_tenant_id() / has_tenant_role()).
  Privileged, cross-cutting operations run in Edge Functions with the service
  role after verifying the caller.

  Profile / session
    users (self row)                 RLS (self)        — read/update own profile
    memberships (own)                RLS (self)        — tenant + role resolution
    role_permissions                 RLS (own role)    — permission grants

  Sites / departments (tenant-scoped via RLS)
    sites      select/insert/update  read:sites / manage:sites
    sites      delete                admin:tenant (cascades)
    departments select/ins/upd/del   read:/manage:departments

  Compliance
    attendance_records (read)        read:compliance — BCEA summary computed
                                     client-side over RLS-scoped rows

  Privileged Edge Functions (service role; caller verified inside)
    tenant-provision            PUBLIC  — create tenant + subscription + invite
                                          admin auth user + admin membership
    tenant-invite-member        invite:members (owner/admin/manager) — invite
                                          auth user + 'invited' membership
    tenant-remove-member        manage:members — set membership 'offboarded'
    access-request-create       PUBLIC  — insert pending access_request
    access-request-approve      approve:access-requests — invite auth user +
                                          'invited' membership, mark approved
    tenant-billing-sync         billing webhook — upsert subscription + status

  Auth user lifecycle (Supabase Auth)
    sign in                     supabase.auth.signInWithPassword
    sign out                    supabase.auth.signOut
    password reset / set        resetPasswordForEmail / updateUser
    new auth user               handle_new_user() trigger mirrors public.users
                                and activates the matching invited membership


D. FRONTEND GATING
-------------------------------------------------------------------------------
  AuthContext.usePermissions(): hasPermission / hasAnyPermission / hasAllPermissions
  ProtectedRoute requiredPermissions={[...]} (any-of) — used by:
    /app/employees-management  -> read:members
    /app/compliance            -> read:compliance
  SitesAndDepartments page:
    Add/Edit Site        -> manage:sites
    Delete Site          -> admin:tenant
    Add/Edit/Delete Dept -> manage:departments


E. SUPABASE SETUP CHECKLIST
-------------------------------------------------------------------------------
  1. Apply migrations (supabase db push) to your schema project, including
     20260616000000_remove_auth0_integration.sql, then regenerate types:
       supabase gen types typescript --linked > src/integrations/supabase/types.ts
  2. Auth settings: enable Email/password sign-in. Configure the Site URL and
     additional redirect URLs (/reset-password) for invite + recovery links.
  3. Email templates: customise the Invite and Reset Password templates (the
     invite flow emails a set-password link that lands on /reset-password).
  4. Edge Function secrets: SUPABASE_URL, SUPABASE_ANON_KEY,
     SUPABASE_SERVICE_ROLE_KEY, PUBLIC_SITE_URL. Deploy the functions with
     `supabase functions deploy`.
  5. Frontend env: VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY.

  NOTE: Permissions are a global capability layer. Tenant data isolation remains
  enforced by public.memberships + Postgres RLS — never rely on a permission
  alone for the tenant boundary.
