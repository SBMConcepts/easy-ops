===============================================================================
 EasyOps — RBAC Reference (Access Tiers + Route Map)
===============================================================================
 Model        : Access tiers (NOT fine-grained permissions). A caller's tier is
                org_members.role, one of: owner > admin > member > viewer.
 Token claims : The Auth0 post-login Action injects `org_id` and `role` as
                namespaced custom claims on the ID + access tokens.
 Namespace    : https://easyops.us.auth0.com/   (server/lib/auth.ts AUTH0_CLAIM_NS,
                src/lib/auth0-config.ts, auth0/actions/post-login.js, DB org_id()).
 Enforcement  : backend  -> requireAuth + requireOrg + requireRole(minTier)
                            (server/lib/auth-middleware.ts, server/lib/rbac.ts)
                frontend -> <ProtectedRoute allowedRoles={[...]}>, useAuthRole()
                DB        -> public.org_id() + Row-Level Security scope by org_id

 NOTE: The earlier fine-grained model (public.role_permissions, app_permission
 enum, requirePermission(), has_permission()) was REMOVED in the schema v2
 refactor. Gating is now purely tier-based.
===============================================================================


A. ACCESS TIERS  (org_members.role)
-------------------------------------------------------------------------------
  Tier      Rank  Meaning
  owner      3    Organization owner — full control.
  admin      2    Administrator — manage members, sites, departments, billing.
  member     1    Standard member — read org data, record own attendance.
  viewer     0    Read-only.

  requireRole(min) / hasMinRole(min) pass when rank(role) >= rank(min).


B. JOB ROLES vs ACCESS TIERS
-------------------------------------------------------------------------------
  Job roles (org_roles.name, the organization_role enum) describe a person's
  POSITION and are distinct from access tiers. Mapping (rbac.ts jobRoleToTier):

    job role      -> access tier
    owner         -> owner
    admin         -> admin
    manager       -> admin
    supervisor    -> member
    employee      -> member
    (unknown)     -> viewer


C. ROUTE -> ACCESS MAP  (Express API; server/app.ts mount order)
-------------------------------------------------------------------------------
  Public (no token)
    POST   /api/organizations                 create org (pre-signup intake)
    GET    /api/org-lookup                     resolve org by ?slug= or ?email=

  Identity-provider webhook (x-api-key shared secret)
    POST   /api/auth/sync                      Auth0 post-login Action

  Authenticated, self (requireAuth [+ requireOrg])
    GET    /api/health                         liveness (no auth)
    GET    /api/session                        token echo
    GET    /api/userinfo                       current user profile (+requireOrg)
    PUT    /api/userinfo                        update own profile
    GET    /api/organizations                  current organization (+requireOrg)
    GET    /api/user-credentials/me            own credential status

  member+ (requireRole('member'))
    GET    /api/org-members                    list members
    GET    /api/org-sites                      list sites
    GET    /api/org-departments               list departments
    GET    /api/org-roles                      list job roles
    GET    /api/org-attendance                 list attendance
    POST   /api/org-attendance                 record OWN daily attendance
    GET    /api/subscriptions                  current subscription
    GET    /api/compliance                     BCEA compliance summary

  admin+ (requireRole('admin'))
    POST   /api/onboarding/complete            finalize onboarding
    POST   /api/org-members                    set a member's access tier
    DELETE /api/org-members/:id                remove a member
    POST   /api/invitations                    invite a person to the org
    POST   /api/org-sites                      create site
    PATCH  /api/org-sites/:id                  update site
    DELETE /api/org-sites/:id                  delete site
    POST   /api/org-departments               create department
    PATCH  /api/org-departments/:id           rename department
    DELETE /api/org-departments/:id           delete department
    POST   /api/org-roles                      add a job role
    DELETE /api/org-roles/:id                  remove a job role
    PATCH  /api/subscriptions                  update plan/status
    PATCH  /api/user-credentials/:auth0UserId/status
                                               enable/disable a credential
                                               (guarded to caller's org)

  SECURITY: /api/user-credentials never returns password_hash (the bcrypt store
  used by the Auth0 custom-database scripts in auth0/database-scripts/).

  GAP: the frontend (src/hooks/useAccessRequestApi.ts) still calls
    GET  /api/access-requests
    POST /api/access-requests/approve-and-invite
  but there is NO server route for these (the access_requests table is not part
  of schema v2). Treat as unimplemented until reintroduced.


D. FRONTEND GATING  (src/App.tsx + useAuthRole)
-------------------------------------------------------------------------------
  <ProtectedRoute allowedRoles={[...]}> redirects:
    - unauthenticated            -> /login
    - no organization (tenant)   -> /login
    - admin + org provisioning   -> /app/onboarding
    - role not in allowedRoles   -> /app

  Route                         allowedRoles
    /app (index dashboard)      role-routed by DashboardRouter
    /app/check-in               owner, admin, member, viewer
    /app/live-attendance        owner, admin, member, viewer
    /app/compliance             owner, admin, member, viewer
    /app/sites                  owner, admin, member, viewer
    /app/payroll                owner, admin, member, viewer
    /app/settings               owner, admin, member, viewer
    /app/employees-management   owner, admin
    /app/onboarding             (no wrapper; redirect handled in ProtectedRoute)
    /app/reports                (no wrapper)

  useAuthRole(): hasMinRole(tier), isOwner, isAdmin (>=admin), isMember (>=member).
  SitesAndDepartments page hides create/edit/delete controls unless isAdmin
  (canManageSites / canManageDepartments); reads are open to all tiers.


E. AUTH0 SETUP CHECKLIST
-------------------------------------------------------------------------------
  1. Custom API (Applications -> APIs), identifier = AUTH0_AUDIENCE. RBAC is not
     required for tier gating, but the API must exist so access tokens are JWTs.
  2. Post-login Action (auth0/actions/post-login.js) secrets:
       BACKEND_URL        — Express server base URL
       AUTH0_SYNC_SECRET  — must equal server AUTH0_SYNC_SECRET (x-api-key)
     The Action calls POST /api/auth/sync, then injects `org_id` + `role` claims.
  3. Claim namespace must match across the Action, frontend
     (src/lib/auth0-config.ts AUTH0_CLAIM_NS) and server
     (server/lib/auth.ts AUTH0_CLAIM_NS): https://easyops.us.auth0.com/
  4. Organizations: each tenant is an Auth0 Organization; the org id is the
     organizations.auth0_org_id primary key and the JWT `org_id` claim.

  NOTE: Access tiers are a global capability layer. Tenant data isolation is
  enforced by org_id + Postgres RLS — never rely on a tier alone for the
  tenant boundary.

F. CUSTOM API SCOPES (OPTIONAL)  — Applications -> APIs -> [API] -> Permissions
-------------------------------------------------------------------------------
  Convention: verb:resource. These map 1:1 to the schema/routes above.

  IMPORTANT: enforcement today is ACCESS-TIER based (requireRole + DB checks),
  NOT scopes. Loading these is optional — useful only if you later (a) surface
  RBAC roles in the Auth0 dashboard, (b) gate scopes per machine-to-machine
  client, or (c) move to permission-based middleware. If you adopt them, enable
  "RBAC" + "Add Permissions in the Access Token" on the API and assign scopes to
  Auth0 roles that mirror the tiers in section A.

  Organizations & onboarding
    create:organizations   Create a new organization (public provisioning)
    read:organizations     View the current organization profile and settings
    update:organizations   Update organization name, status, slug, metadata
    manage:onboarding      Complete onboarding (sites/departments/roles + activate)

  Members (org_members)
    read:members           List members of the organization
    create:members         Add a member and assign an access tier
    update:members         Change a member's access tier or status
    delete:members         Remove a member from the organization

  Invitations
    read:invitations       View pending and sent invitations
    create:invitations     Invite a person to the organization
    delete:invitations     Revoke a pending invitation

  Sites (org_sites)
    read:sites             View organization sites
    create:sites           Create a new site
    update:sites           Update site details (address, geofence, etc.)
    delete:sites           Delete a site

  Departments (org_departments)
    read:departments       View departments
    create:departments     Create a department
    update:departments     Rename or update a department
    delete:departments     Delete a department

  Job roles (org_roles)
    read:roles             View the organization's job roles
    create:roles           Add a job role
    delete:roles           Remove a job role

  Attendance (org_attendance)
    read:attendance        View attendance records (own or org-wide per tier)
    create:attendance      Record a daily attendance entry

  Subscriptions & billing
    read:subscriptions     View the current plan and billing status
    update:subscriptions   Change plan, seats, or billing status

  Compliance
    read:compliance        View BCEA compliance summaries and violations

  User profile & credentials
    read:profile           Read the current user's own profile
    update:profile         Update the current user's own profile
    read:credentials       Read own credential status (never the password hash)
    manage:credentials     Enable/disable/block a user's login credential (admin)

  Audit logs (audit_logs)
    read:audit-logs        View the organization's audit trail

  Suggested tier -> scope mapping (mirrors rbac.ts tiers)
    viewer   all read:* scopes
    member   viewer + create:attendance, read:profile, update:profile
    admin    member + all create:*/update:*/delete:*, manage:onboarding,
             manage:credentials, update:subscriptions
    owner    admin + create:organizations (full control)
